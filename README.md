## 📌 简介

将结构化客户/线索画像转化为标准需求文档(SRS)、系统架构、智能体方案或解决方案提案，含 BR/UR/FR/NFR 编号与需求追溯矩阵。适用于销售/售前对客户线索(C00x)做标准化产出。

## 📖 使用说明（完整规范）

> 以下为该技能的完整说明，涵盖核心能力、工作流程与关键规则，帮助您全面了解其运作方式。

## 触发条件
用户粘贴结构化客户画像（含 行业 / 规模 / License / 地区 / 核心亮点 / 场景标签 / 客户简介 / 需求痛点(①②③…) / AI应用场景 / 预期收益），并要求"输出需求文档 / SRS / 架构 / 智能体方案 / 解决方案提案 / 初步完成"。

## 输入解析（必填字段提取）
从画像抽取：行业、规模、地区、License、痛点列表、AI应用场景、预期收益指标、场景标签。若字段缺失，按已有信息合理补全并在文中标注"待确认"。

## 四步全链路产出（可按需取用任一步，或一气呵成）
整体链路：**画像 → 需求文档(SRS) → 系统架构 → 智能体方案 → 整合总览**。每一步的产出都引用上一步编号，保证可追溯。

**A. 需求文档（SRS）** —— 章节结构：
0. 文档说明与需求编号规范
1. 项目背景与目标（含客户给定量化目标）
2. 干系人与用户角色
3. 业务需求（BR）：组织级目标，引用痛点来源
4. 用户需求（UR）：角色级诉求，引用场景
5. 功能需求（FR）：每条含 输入 / 处理 / 输出 / 规则 / 验收口径
6. 非功能需求（NFR）：安全·权限·审计·防误删·合规·易用性·性能·可靠性·可观测
7. 数据需求（DR）：模板库、知识库(RAG)、案卷、主数据
8. 验收标准与 KPI（对齐客户收益指标 + 度量方式）
9. 约束、假设与依赖、边界
10. 实施阶段（参考三阶段路线）
附录 A：需求追溯矩阵（痛点/场景 → BR → UR → FR → NFR → 收益）

**B. 系统架构** —— 在 SRS 末尾追加「系统架构设计」章（编号顺延），并生成架构图 SVG：
- 架构原则：数据不出域、分层解耦、安全横切、人工终审（逐条对应 NFR）。
- 逻辑分层（6 层）：接入层 / 应用与 Skill 层 / AI 能力层 / 数据层 / 安全合规层（横切，红色贯穿）/ 运维观测层。
- 部署架构：私有化/专属工作区，License 按角色分配。
- 关键数据流：以某一场景为例的端到端流程。
- 技术选型建议：平台底座、检索、抽取、合规的具体指向。
- 架构图 SVG：viewBox `0 0 680`，≤2 色系（gray 结构 + red 安全强调），可由 Visualizer 内联预览。

**C. 智能体（Agent）方案** —— 章节结构：
0. 文档说明（标注上游 SRS/架构）
1. 智能体总体设计（1 编排 + N 专家 + 共享知识层 + 横切安全护栏）
2. 智能体矩阵表（智能体 / 职责 / 对应 FR / 服务对象）
3. 智能体设计卡（每个含 9 要素：角色 / 目标 / 输入 / 工具 / 知识 / 输出 / 约束 / 人工节点 / 异常）
4. 多智能体协作流程（以某场景为例的端到端链路）
5. 安全与合规护栏（横切，作用于每个智能体：输入鉴权/过程审计/输出终审/防误删/不出域/合规红线）
6. 知识库与记忆机制（短期会话 / 长期 RAG / 案例回流飞轮）
7. 评估与验收（智能体维度指标，对齐 SRS 的 KPI）
8. 集成与接入（入口 + 对接系统）
9. 实施路线图（沿用三阶段）
附录：智能体 ↔ 需求追溯（智能体 / BR / FR / NFR）
- 配套 智能体编排图 SVG：编排+专家+共享知识层+横切护栏(虚线包围)+人工终审，≤2 色系（gray 结构 + blue 智能体）。

**D. 解决方案提案** —— 章节结构：
背景与客户概况 → 痛点诊断(表格) → 方案总览(平台+Skill矩阵) → 四大场景详细 → 预期收益(对齐客户目标) → 安全与合规设计 → 落地路线图 → 商务建议。
配套两张 SVG 可视化：①能力映射图(痛点→能力中枢→收益)；②三阶段落地路线图。可用 Visualizer（read_me 加载 diagram 模块）内联呈现。

**E. 初步完成 / 整合总览** —— 当链路 A→B→C 已产出后，生成一份「初步完整方案(总览)」作为统一入口：
- 执行摘要（对外一页讲清 痛点→方案→收益→安全）。
- 分章精炼引用 A/B/C 的编号与结论（不重复全文）。
- 交付物清单 + 全链路追溯附录（痛点/场景 → 需求 → 架构 → 智能体）。

## 需求编号规范
- BR 业务需求 / UR 用户需求 / FR 功能需求 / NFR 非功能需求 / DR 数据需求
- 每条含：编号、描述、来源(对应痛点/场景)、优先级(P0 必备 / P1 重要 / P2 增强)、验收口径
- 编号连续，便于后续方案设计、任务拆分与验收追溯

## 关键原则
- **敏感行业（法律/金融等）**：安全合规为第一性原则——数据不出域、最小权限+审计、版本管理+防误删+人工复核、AI 仅出初稿且强制人工终审、严守《律师法》《广告法》等红线。
- 预期收益须对齐客户给定指标，并给出可度量的口径。
- 默认输出 Markdown；如需 .docx / .pptx 调用 `minimax-docx` / `pptx-generator` 技能导出。
- 架构图 / 编排图遵循 Visualizer 规范（viewBox `0 0 680`、≤2 色系）。
